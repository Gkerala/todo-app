# Todo 앱 (로컬 SQLite → Supabase)

할 일을 추가·완료·삭제하고, 마감일·태그·오늘 할 일·검색을 지원하는 작은 Todo 앱. 기획은 [PRD.md](PRD.md).

시연 영상(2분 28초): [demo/demo.mp4](demo/demo.mp4) · 앞부분은 로컬(SQLite) 모드(이전 화면), 뒷부분은 Supabase(클라우드) 모드(새 화면). 내용은 아래 "시연 영상에서 다룬 동작" 참고

## 직접 써 보기 (채점자 안내)
**접속 주소: https://aiffel-work.onrender.com/**
- 무료 서버라 한동안 쓰지 않으면 잠들어 있어서, **첫 접속에 약 1분** 걸릴 수 있어요. 화면이 안 뜨면 잠시 뒤 새로고침하세요.
- 처음이면 이메일과 비밀번호(8자 이상)를 적고 **회원가입**을 누르세요. 이메일 인증이 없어서 형식만 맞으면 돼요. 실제 이메일이 아니어도 됩니다.
- 써 볼 기능: 할 일 **추가**(마감일, 태그는 쉼표로 구분) · **완료** 체크 · **삭제** · **오늘 할 일만** · **검색** · **태그 클릭**으로 거르기 · **새로고침 후 유지**
- 계정을 두 개 만들면(로그아웃 후 다른 이메일로 가입) **서로의 할 일이 보이지 않는 것**(RLS)도 확인할 수 있어요.
- 서버를 껐다 켜도 남는지(로컬)와 계정 분리는 시연 영상에, RLS 12개 항목 같은 개발자 확인은 아래 "확인 기록"에 있어요.

## 실행 방법
```bash
npm install
npm start              # 로컬 (SQLite, todo.db 파일, 로그인 없음)   → http://localhost:3000
npm run start:cloud    # 클라우드 (Supabase, 로그인 필요)            → http://localhost:3000
npm run check:rls      # 계정 A/B로 RLS 확인 (클라우드 서버를 켠 뒤)
```
`.env`는 `.env.example`을 복사해서 채운다 (GitHub에 올리지 않음).
Supabase 표와 RLS 정책은 `supabase/schema.sql`을 SQL Editor에서 실행해 만든다.

## 구조
```
브라우저 ─(로그인 토큰)→ server.js ─(그 사용자 토큰으로)→ Supabase DB (RLS가 "내 행만" 검사)
                          └ store-sqlite.js / store-supabase.js  (저장 방식 2개, 함수 4개 동일)
```
- 화면은 백엔드 API에만 요청한다. DB 접근 코드는 `db.js`, `store-*.js`(서버 쪽)에만 있다.
- 키는 `.env`에서 환경변수로 읽는다. Secret(service_role) 키는 RLS를 무시하므로 쓰지 않는다.

## 확인 기록
| 확인 항목 | 로컬 (SQLite) | Supabase | 확인 방법 / 날짜 |
|---|---|---|---|
| 추가 후 새로고침해도 남음 | 성공 | 성공 | 두 모드 모두 브라우저에서 추가 후 새로고침, 2026-10-29 |
| 앱을 껐다 켜도 남음 | 성공 | 성공 | 두 모드 모두 서버를 껐다 켠 뒤 목록 유지 확인, 2026-10-29 |
| 완료·삭제 동작 | 성공 | 성공 | 두 모드 모두 화면에서 완료 표시·삭제 확인, 2026-10-29 |
| 다른 계정 데이터가 안 보임 (RLS) | - | 성공 | 화면에서 계정 A·B로 로그인해 확인 + `npm run check:rls` 12개 항목 모두 통과, 2026-10-29 |
| 배포 | - | 배포함, 준비물 기록함 | 아래 "Render 배포" 참고 |

**클라우드 전환 기록 (한 줄)**: 로컬 SQLite 저장소를 Supabase(Postgres)로 옮겼다. `supabase/schema.sql`로 표 3개를 만들고 `user_id`를 추가했으며, RLS를 켜고 "내 행만" 정책 3개를 걸었다. 로그인은 Supabase Auth, 접속 키는 `.env`에 두고 백엔드에서만 쓴다. (2026-10-29)

**RLS 확인 기록 (한 줄)**: 계정 A가 만든 할 일을 계정 B가 보기·수정·삭제할 수 없고, 로그인 없는 요청도 거절됨을 화면과 `npm run check:rls`(12/12)로 확인했다. (2026-10-29)

RLS 확인 내용 (`scripts/rls-check.js`):
- 백엔드를 거쳐: B가 A의 할 일을 못 보고, 수정·삭제 요청은 거절(404)되며, A의 원래 할 일은 그대로.
- 백엔드를 거치지 않고 DB에 직접: B의 조회·수정은 0행, A의 `user_id`로 만들기는 거절(42501).
- 로그인 없이 요청하면 401.

## Render 배포 (실제 배포함: https://aiffel-work.onrender.com/)
Render에 이 저장소(`Gkerala/todo-app`, 브랜치 `main`)를 연결해 배포했다. 앱이 저장소 맨 위에 있어서 설정이 단순하다. (서비스 이름이 `aiffel-work`라서 접속 주소에도 그 이름이 들어 있다.)
- **Root Directory**: 비움
- **Build command**: `npm install`
- **Start command**: `node server.js supabase`
  (`npm run start:cloud`는 `.env` 파일을 읽도록 되어 있어서, 파일이 없는 Render에서는 쓰지 않는다.)
- **환경변수**(Render 대시보드에 입력): `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`.
  `SUPABASE_DB_PASSWORD`, `TEST_*`는 넣지 않는다. 앱 코드가 쓰지 않는다.
- **PORT**: Render가 지정해 주며 서버가 `process.env.PORT`를 읽는다.
- **Node 버전**: 지정하지 않았다. Render 기본 버전(공식 문서 기준 24.x)이 로컬(v24)과 같은 계열이다.
- **자동 배포**: `main`에 푸시하면 Render가 새로 배포한다(Events의 "Branch updated").
- **주의**: 무료 서버는 15분간 요청이 없으면 잠들고, 깨어나는 데 약 1분이 걸린다(Render 공식 문서). Supabase 무료 프로젝트도 1주 미사용 시 일시정지될 수 있다.
- **정상 작동 확인**: 배포 URL 뒤에 `/api/config`를 열어 `{"mode":"supabase","login":true}`가 나오는지 보고, 로그인 후 할 일 추가.

**배포하며 겪은 문제**
1. Start Command를 비워 두면 Render가 `node index.js`로 실행한다. 이 앱에는 `index.js`가 없어 `Cannot find module`로 실패했다. → `node server.js supabase`로 지정.
2. 이 앱이 `aiffel-work` 저장소 안의 한글 이름 폴더에 있을 때는 Render의 Root Directory 칸이 영문·숫자·`-`·`_`·`.`·`/`·공백만 받아서(한글 경로 거부), 칸을 비우고 명령어에서 `cd <폴더> && ...`로 이동했다. 2026-10-30에 앱을 독립 저장소로 옮긴 뒤에는 폴더 이동이 필요 없어져 위의 단순한 설정으로 바꿨다.

## 퀘스트 C-2 (에이전트 코드리뷰)
이 Todo 앱은 퀘스트 C-2 코드 페어리뷰의 대상이기도 하다. 리뷰어가 **계정·`.env` 없이** 받아서 실행해 볼 수 있도록 **로컬(SQLite) 전용 폴더**를 퀘스트 저장소에 따로 두었다.
- **퀘스트 C-2 저장소** (리뷰어용 `Todo-로컬버전/` 폴더, 퀘스트 요약, 리뷰 양식 포함): [Gkerala/2-quest-agent-code-review](https://github.com/Gkerala/2-quest-agent-code-review)
- 로컬 버전의 코드는 이 저장소에서 **그대로 복사한 스냅샷**이다. 이 저장소의 코드를 고치면 그쪽도 같이 갱신한다.
